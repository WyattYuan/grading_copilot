# 1 摘要（10 分）
本项目旨在开发一个基于人机协同理念的 AI 助教智能评分与分析系统。系统利用大语言模型（如 GPT-4o 或 Qwen-Plus）对学生提交的文本和代码类作业进行自动评分，并通过 Langchain 框架确保评分结果的结构化和可靠性。核心功能包括：通过 FastAPI 后端实现的批量并发处理，将评分效率提升近10倍；基于 Streamlit 的现代化前端，提供详细的评分报告展示、人工审核与微调、以及成绩可视化分析功能。系统通过“报告为源，表格为派生”的设计模式，确保了 AI 评分与人工调整后数据的一致性，最终实现提升评分效率与保障评分质量的双重目标。

# 2 背景和意义（20 分）
在教育领域，尤其是高等教育中，教师批改大量学生作业是一项耗时且重复性高的劳动。传统人工评分不仅效率低下，还容易因主观因素导致评分标准不一。随着人工智能技术，特别是大语言模型的飞速发展，利用 AI 辅助教学活动成为可能。

本项目正是基于此背景，旨在探索 AI 在教育评分场景下的应用。其核心意义在于：
1.  **提升效率**：将教师从繁重的重复性评分工作中解放出来，使他们能更专注于教学设计和学生互动等创造性活动。
2.  **保证一致性**：AI 能够严格、不知疲倦地遵循预设的评分标准，有效减少不同学生、不同时间点评分的客观偏差。
3.  **人机协同**：本项目并非要完全替代教师，而是构建一个人机协同的工作流。AI 提供高效的初步评分和详细的评分依据，而最终的判断权和调整权仍在教师手中，确保了评分的权威性和准确性。
4.  **数据驱动的教学洞察**：系统生成的结构化评分数据和可视化分析，可以帮助教师快速了解学生的整体掌握情况和普遍的知识薄弱点，为后续的教学改进提供数据支持。

通过本系统，我们期望构建一个更高效、更公平、更智能的现代化教育评分解决方案。

# 3 技术方案（50 分）
## 3.1 设计思路
本项目的整体设计遵循前后端分离的原则，并以数据一致性和高并发处理为核心考量。

**1. 系统架构**
系统分为三层，各司其职：
- **表示层 (Frontend)**: 采用 `Streamlit` 构建，负责用户交互。提供文件上传、任务状态监控、评分结果展示、人工微调界面和数据可视化图表等功能。
- **应用层 (Backend)**: 采用 `FastAPI` 构建，作为业务逻辑核心。负责处理 HTTP 请求、管理评分任务、文件解析（ZIP、docx 等）、以及通过异步任务调度实现高并发评分。
- **智能层 (Intelligence)**: 采用 `Langchain` 集成大语言模型（GPT-4o/Qwen-Plus），作为系统的“评分大脑”。通过结构化输出（Structured Output）功能，确保 AI 的评分结果遵循预定义的 Pydantic 模型，保证了数据的可靠性和格式一致性。

**2. 数据一致性模型**
为解决 AI 评分与人工微调可能导致的数据不一致问题，系统采用了 **“报告为源，表格为派生”** 的设计理念：
- **单一事实来源 (Single Source of Truth)**: 每道题目的评分结果（包括 AI 评分、人工调整分数、评分理由等）都保存为一个独立的 JSON 报告文件 (`report_{student_id}_{question_id}.json`)。这是系统中最原始、最可信的数据。
- **派生数据**: 用户看到的总分表 (`summary_table.csv`) 是一个派生视图。它在需要时通过遍历指定任务的所有 JSON 报告文件动态生成。
- **自动同步**: 当教师通过 UI 对任何一份报告进行修改后，系统会通过 `SyncManager` 自动触发总分表的重新生成，从而确保总览数据与详细数据永远保持一致，无需人工干预。

这种设计不仅保证了数据一致性，还使得系统状态可追溯、易于调试。

## 3.2 详细实现过程
项目的具体实施过程遵循一个清晰的工作流：

1.  **准备与上传**:
    *   教师根据 `exam_config.json` 格式准备好包含题目描述、参考答案和详细评分标准的配置文件。
    *   将所有学生答案文件（支持 `.txt`, `.docx`, `.md` 格式）打包成一个 ZIP 文件。
    *   在 Streamlit 前端界面，用户上传这两个文件，后端启动一个唯一的评分任务（`job_id`）。

2.  **文件解析与任务分发**:
    *   FastAPI 后端接收文件，使用 `aiofiles` 和 `zipfile` 异步解压学生答案。
    *   系统解析 `exam_config.json` 和每个学生答案文件，提取出学生信息和各题作答，并根据题目 ID 进行匹配，生成一系列独立的评分子任务。

3.  **AI 并发评分**:
    *   为了提升性能，系统采用 `asyncio.gather` 对评分任务进行分批并发处理。并发批次大小（`GRADING_BATCH_SIZE`）可在 `.env` 文件中配置。
    *   每个子任务调用 `GradingAgent`，该代理将题目信息和学生答案格式化后，发送给大语言模型。
    *   Langchain 的 `with_structured_output` 功能确保 LLM 返回一个符合 `GradingResult` Pydantic 模型的结果，包含分数和详细的评分理由。

4.  **生成与存储报告**:
    *   评分完成后，系统为每个子任务生成一个 `GradingReport` JSON 文件，存储在 `data/reports/job_{job_id}/` 目录下。该报告包含学生信息、题目信息、AI 评分、AI 评分依据、以及用于人工微调的字段。
    *   所有报告生成后，`SyncManager` 会自动汇总生成初始的 `summary_table.csv`。

5.  **人工审核与微调**:
    *   UI 界面以可交互的表格形式展示 `summary_table.csv` 的内容。
    *   教师可以点击查看任何一个学生的任何一道题的详细评分报告，其中包含学生的原始答案和 AI 给出的评分理由。
    *   如果教师认为 AI 评分不当，可以直接在界面上修改分数并填写“人工调整理由”。

6.  **数据同步与导出**:
    *   当教师提交修改后，前端调用后端 API 更新对应的 JSON 报告文件。
    *   `SyncManager` 监听到报告文件的变更，立即重新计算并覆盖旧的 `summary_table.csv`，UI 上的总分表也随之刷新。
    *   教师完成所有审核后，可以一键导出最终的总分表（CSV 格式），用于后续的成绩录入。

## 3.3 大模型关键提示词
为了确保大模型能够严格、一致地按照我们的要求进行评分，我们设计了专业的系统提示词（System Prompt）和用户提示词模板（Human Prompt）。

**1. 系统提示词 (System Prompt)**
该提示词为模型设定了其作为“课程助教”的角色和必须遵守的核心规则。
```
你是一个严格的、专业的课程助教。
你的任务是根据 [评分标准] 来评判 [学生作答]。

重要规则:
1. [参考答案] 仅供你参考理解题意，[评分标准] 才是你给分的唯一依据
2. 必须逐条对比评分标准，给出详细的评分依据
3. 评分必须严格、公正、一致
4. 如果学生答案与参考答案表述不同但意思正确，也应该给分
5. 必须指出学生答案的优点和不足
6. 总分不能超过题目满分
```

**2. 用户提示词 (Human Prompt)**
该提示词模板用于在每次调用时，将具体的题目信息、评分标准和学生答案结构化地提供给模型。
```
【题目描述】
{question_description}

【题目满分】
{max_score} 分

【参考答案】
{reference_answer}

【评分标准】
{scoring_criteria}

【学生作答】
{student_answer}

请严格按照评分标准，给出你的评分和详细依据。评分依据必须逐条说明学生在每个评分标准上的表现。
```
通过这种“角色设定 + 规则约束 + 结构化输入”的提示词工程，我们最大限度地保证了 AI 评分的质量和可靠性。

## 3.4 插件、知识库、数据库、工作流等（若使用扣子）
本项目未使用“扣子（Coze）”智能体开发平台，而是基于开源框架 `Langchain` 进行定制开发。

在本项目中，可以类比于“插件”或“工具”的核心功能是 **Langchain 的结构化输出（Structured Output）能力**。

- **实现方式**: 我们定义了一个 Pydantic 模型 `GradingResult`，用于描述期望的评分返还格式（包含 `score` 和 `rationale` 两个字段）。然后，通过调用 `.with_structured_output(GradingResult)` 方法，将这个模型绑定到 LLM 上。
- **作用**: 这使得 Langchain 能够根据 Pydantic 模型自动生成符合特定 LLM 的提示，并解析其返回的 JSON 字符串，确保每次模型调用都返回一个格式正确、类型安全的数据对象。这极大地增强了系统的稳定性和可靠性，避免了手动解析和验证模型输出的复杂工作。

本项目不涉及外部知识库或独立的数据库，所有任务数据均以文件形式（JSON, CSV）存储在本地文件系统中，实现了轻量化和易于部署的特点。

# 5 总结与建议（10 分）
**收获与体会**:
本项目成功地将大语言模型应用于教育评分场景，构建了一个完整、高效且可靠的人机协同评分系统。最大的收获在于：
- **工程实践**: 深入实践了前后端分离架构，并应用了 FastAPI 和 Streamlit 等现代化 Python Web 框架。
- **AI 应用**: 掌握了通过 Langchain 对大模型进行封装和调用的方法，特别是提示词工程和结构化输出在保证 AI 输出质量上的关键作用。
- **性能优化**: 通过 `asyncio` 实现了高并发处理，直观地感受到了异步编程在 I/O 密集型任务中的巨大优势。
- **设计模式**: “报告为源，表格为派生”的数据一致性方案，为处理类似“AI生成 + 人工修改”的场景提供了可靠的解决方案。

**建议与展望**:
- **模型能力**: 目前的评分质量高度依赖于通用大模型的能力。未来可以探索使用特定领域的语料对模型进行微调（Fine-tuning），以期在专业领域的评分上达到更高精度。
- **功能扩展**: 可以增加对更多文件格式（如 PDF、图片）的支持，以及对编程题进行动态代码执行和功能测试的能力。
- **用户体验**: 可以进一步优化前端交互，例如提供更丰富的可视化分析维度、支持对评分报告进行批量操作等。
